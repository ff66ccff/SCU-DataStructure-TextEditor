## 0. 结论速览（先行）

| # | 决策点 | 推荐结论 | 一句话理由 |
|---|---|---|---|
| D1 | 链表形态 | 双向链表 + **头哨兵 + 尾哨兵**（2 个哨兵） | 插入/删除统一为「在 p 之后插」「摘除 p」，消除首尾特判 |
| D2 | 当前行表示 | **Node\* current**（不存行号） | 规则 2 要求替换后当前行结点不变，指针天然满足；行号是派生量 |
| D3 | 行内容所有权 | 每结点独占一份 new char[]，'\0' 结尾；长度 = 内容长度 | 规则 3；空行 = 指向 1 字节 '\0' 的数组，**不是 nullptr** |
| D4 | 替换内存策略 | 一律「先分配新数组 → 拷贝 → 成功后再释放旧数组」 | 分配失败或无匹配时不破坏原状态，杜绝悬垂 |
| D5 | 子串替换算法 | 双指针单遍，读原文、写新缓冲；命中后**读指针 += needle 长度** | 保证不重叠、不回头、不重扫本次新生成内容（规则 5） |
| D6 | 统计 | 不缓存，命令时 O(n + 总字符数) 重算 | 缓存引入多处失效风险；统计命令本身必须遍历内容 |
| D7 | 换行处理 | 读：接受 LF 与 CRLF，行结束标记不入内容；写：统一 '\n' | 规则 6/7 明确不要求保留原编码与末尾换行形式 |
| D8 | 空文档判据 | current == nullptr 且 head->next == tail | 规则 1；与「内容是空串的数据结点」严格二分 |
| D9 | 命令风格 | 单字符命令 + 行尾余下文本作参数；子串替换用 s /old/new/ | 降低解析复杂度，注意力留给链表与字符串 |
| D10 | 扩展命令 | 全部使用**新增独立字符**（如 x 导出快照），不改写基础命令含义 | 指导书：扩展功能使用单独命令，不改变基础命令的含义 |

## 2. 数据结构选型：双向链表结点与哨兵

### 2.1 两个候选方案

**方案 A — 无哨兵**：head / tail 直接指向首 / 末数据结点，空文档 head == tail == nullptr。

**方案 B — 双向 + 头尾哨兵（推荐）**：head、tail 为固定存在的哨兵结点（content 为 nullptr / 空串，不参与显示与统计）。空文档判据 head->next == tail。

### 2.2 取舍对比

| 维度 | 方案 A 无哨兵 | 方案 B 头尾双哨兵 |
|---|---|---|
| 空文档表示 | head == tail == nullptr | head->next == tail |
| 插入第一行 | 必须分支：head == nullptr 时改 head 与 tail | 统一 insertAfter(head, node)，无分支 |
| 删除首行 / 末行 | 必须更新 head / tail 本身 | 统一 unlink(p)，head/tail 永不改变 |
| 代码分支数 | 多（首尾 4 种组合） | 少（一种） |
| 内存开销 | 省 2 个结点 | 多 2 个结点（可忽略） |
| 遍历 / 统计 | 直接遍历 | 必须显式跳过哨兵（新易错点） |
| 调试安全性 | head 悬垂后整表不可达 | head/tail 恒有效，判空即 head->next == tail |
| 可视化（表 9） | 直接画 head/tail | 表 9 已明确要求「使用哨兵时将其与数据结点区分」，规范可满足 |
| 变体方案 | — | 仅头哨兵：末行/尾部插入仍需 O(n) 遍历，**不推荐** |

### 2.3 推荐与理由

**推荐方案 B（双向链表 + 头哨兵 + 尾哨兵）**：
1. 插入、删除都退化为「在 p 之后插」「摘除 p」，与规则 2 的「删除当前行后优先取下一行」天然对齐；
2. 空文档与空行的区分用一个表达式判定，规则 1 的实现不会散落在各处；
3. 指导书允许小组自选，表 9 已为哨兵预留了可视化表达，方案 B 不会与选做冲突。

**代价（必须写进实现约束）**：所有遍历/统计/显示必须 `p = head->next; p != tail; p = p->next` 式跳过哨兵；哨兵 content 必须为 nullptr，不得参与字符数累加。

**不缓存计数**：不额外维护 totalLines / totalChars。行数在遍历时计数即可，字符数必须读内容；缓存带来的失效点远多于它节省的时间。

## 3. 行内容所有权与生命周期（dynamic char[]）

### 3.1 核心不变式

- INV-1：每个数据结点**独占**一份 char[]；同一指针同一时刻只有一个拥有者，禁止两个结点共享。
- INV-2：content 必须以 '\0' 结尾，且**已分配字节数 >= strlen(content) + 1**。
- INV-3：结点被销毁前，其 content 必先被释放；不存在「结点还在、内容已释放」的中间态。
- INV-4：content == nullptr 只允许出现在哨兵结点上。

### 3.2 分配 / 替换 / 释放时点表

| 操作 | 何时分配 | 何时释放 | 分配或读取失败时 |
|---|---|---|---|
| 插入 i | 为新行分配 len+1 | 无（除非后续失败，回滚释放新数组与新结点） | 提示失败，保持原文本与 current |
| 替换整行 r | 先分配新数组并拷贝 | **新数组分配成功后**才 free 旧 content，再把指针换到结点上 | 保持原 content 不变 |
| 替换子串 s | 命中数 > 0 时分配 newLen+1 | 同上：成功后再 free 旧 content | 无匹配 → 零次分配；失败 → 原内容不动 |
| 删除 d | 无 | 摘链后 free(content)，再 delete 结点 | — |
| 重新读入 e | 先按新文件**建好整棵新链表** | 新链表全部成功后才整体释放旧链表 | 任一步失败：释放已建的新结点，**保留旧缓冲区**（R8） |
| 保存 w | 无（可选用 std::string 暂存输出） | — | 打开/写入失败 → 明确提示失败 |
| 退出 q | 无 | 遍历释放所有数据结点 content + 结点，最后释放两个哨兵 | — |

### 3.3 缩容策略

**不在原地 realloc / 不维护 capacity**。替换一律走「新分配 + 拷贝 + 成功后再释放旧」：
- 避免 length/capacity 双状态与 realloc 失败后的半成品；
- 等长替换也走同一路径，生命周期只有一条代码路径，审查成本最低；
- 代价是一次多余拷贝，相对于本实验数据规模可忽略。

### 3.4 其他约定

- 允许用 std::string 暂存命令行参数与文件读取的行缓冲；**提交成结点时必须拷贝进 new char[]**（指导书明确要求，不能用 vector/list 代替行链表与行内容）。
- 长度 0 的行仍分配 1 字节并写 '\0'：保证「空行」与「未初始化 / 无结点」在内存上可区分（规则 3）。
- 释放后可选用调试填充（如 0xDD）自检，正式构建不启用。

## 4. 当前行表示、空文档与空行语义

### 4.1 结论：Node* current，不存行号

| 方案 | 问题 |
|---|---|
| 存行号（int curLine） | 插入/删除后其后所有行号漂移，需重算；重新读入后需重新定位；表 9 要求「移动当前行不应表现为结点被重建」，行号模型极易诱导实现者重建结点 |
| **Node\* current（推荐）** | 删除/替换后仍指向同一结点，天然满足规则 2；行号仅在需要显示时 O(n) 派生 |

显示行号的方式：显示命令中**一次遍历**同时累加行号，不要为每个结点各做一次 O(n) 查找。

### 4.2 空文档 vs 空行

| 概念 | 内存状态 | current | 行号 | 统计贡献 |
|---|---|---|---|---|
| 空文档 | head->next == tail，无数据结点 | nullptr | 无 | 0 行 0 字符 |
| 空行（如文件 "\n"） | 存在 1 个数据结点，content = "" | 该结点 | 1 | 1 行 0 字符 |
| 空白行（含空格） | 存在 1 个数据结点，content = "   " | 该结点 | 1 | 1 行 3 字符 |

**无法用「内容为空」判断空文档**，必须用结点链判据；反之也不能用「无当前行」反推「内容为空」。

### 4.3 各操作的空文档分支

| 操作 | current != nullptr | current == nullptr（空文档） |
|---|---|---|
| 插入 i | 插到 current 之后 | **插入到 head 之后**，成为唯一行，并设 current = 新结点（规则 1） |
| 删除 d | 按 R2 选择新 current | 提示「空文档无当前行」，不改变任何状态 |
| 替换整行 r / 子串 s | 正常执行 | 提示，不改变状态 |
| 定位 n/u/f/l/g | 正常执行 | 提示，不改变状态 |
| 查找 / | 从 current 第 1 列向后搜 | 直接返回「未找到」，current 仍为 nullptr |
| 显示 p | 逐行输出并标当前行 | 输出「空文档」提示 |

### 4.4 实现必须保持的链表不变式（对应用户第一周问题④）

- I1（链接一致性）：head->prev == nullptr、tail->next == nullptr；对任意数据结点 p，p->next->prev == p 且 p->prev->next == p。
- I2（内容合法性）：任意数据结点 p，p->content != nullptr，内容不含 '\n'，strlen(p->content) == 记录长度。
- I3（当前行合法性）：current == nullptr ⇔ 无数据结点；否则 current 必是 head->next ..tail->prev 链上的结点。
- I4（可达性）：数据结点仅通过链可达、无环，head->next 链能走遍且仅走遍全部数据结点。

## 5. 规则 4/5：查找与子串替换算法

### 5.1 查找（规则 4）

    从 p = current 开始（空文档直接返回未找到）
    行号 line = 当前行号；对每个数据结点 p：
        行内 offset = 从左往右第一个匹配下标（区分大小写）
        若 offset >= 0：current = p；返回 (line, offset + 1)
        line += 1；p = p->next
    走完（p == tail）仍无匹配：状态完全不变，返回「未找到」

要点：起点是 current 第 1 列，**其之前的行不参与**；列号 = 行内偏移 + 1；命中才修改 current（T06）。

### 5.2 子串替换（规则 5）双指针单遍

    i = 0; j = 0（写指针）
    当 i <= len - m：
        若 memcmp(hay + i, needle, m) == 0：
            写入 repl（长度 r）到 out + j；j += r；i += m      // 关键：跳整段
        否则：
            out[j++] = hay[i++]
    收尾：拷贝剩余 0..m-1 个字符；out[newLen] = '\0'
    用新数组替换旧 content（见 3.2）

三条硬约束：**i 只增不减**、**只读原文**、**新生成内容不进入本轮搜索**。

### 5.3 aaa → aa 替换为 b 的推演

| 步骤 | 读指针 i | 原文剩余 | 判定 | 输出缓冲 | 新 i |
|---|---|---|---|---|---|
| 1 | 0 | aaa | 命中（下标 0..1） | b | 2 |
| 2 | 2 | a | 剩余 1 < m=2，不匹配 | b a | 3 |
| 3 | 3 | — | 结束 | **ba** | — |

结论：结果为 **ba**（1 次替换），**不是 bb**。若误用 i += 1，会得到 bb——这同时违反「不重叠」与「不回头」。

### 5.4 a 替换为 aa 的终止性

读指针每次命中后 += m（此处 m=1），且只读长度不变的原文；i 严格单调递增、每次至少 +1 → 迭代次数 <= n，必然结束。结果 = "aa" 重复 n 次。**终止性由「i 只增 + 只读原文」保证，而不是靠新内容参与搜索后自然终止。**

### 5.5 变长替换的空间计算

设 len 为原行长度，m = |needle|，r = |replacement|，cnt = 不重叠匹配个数（cnt <= floor(len/m)）。

- 一般式：newLen = len + cnt * (r - m)。
- 上界（用于安全分配）：newLen <= len + floor(len/m) * (r - m)（r >= m 时）；r < m 时 newLen <= len - cnt * m。
- 推荐**两遍法**：第一遍扫原文求出 cnt（或直接累加 newLen），第二遍才分配 newLen + 1 并填充。优点：一次精确分配、无越界风险、无需动态扩容。
- 边界：newLen == 0（r == 0 且整行被替换）仍分配 1 字节写 '\0'。
- needle 为空 → 提示并保持原状（规则 5）；无匹配 → **零次分配、内容不变**。

### 5.6 边界推演补充

| 输入行 | 操作 | 结果 | 说明 |
|---|---|---|---|
| aaaa | aa → b | bb | 不重叠：匹配 (0,2) 与 (2,4) |
| aaa | aa → b | ba | 尾部剩余不足一段，不再回退匹配 |
| abab | ab → abab | abababab | 变长且新串含旧串，新串不被重扫 |
| hello | xyz → q | hello | 无匹配，不分配、不改变 |
| hello | he → （空） | llo | replacement 可空，newLen = 3 |

## 6. 统计规则、读取状态机与保存格式（规则 6/7）

### 6.1 表格 3 五个样例逐条推演

字符数 = Σ 各行内容长度（含空格与制表符），**不计行结束标记，不计结尾 '\0'**。

| 文件字节序列 | 读取状态机动作 | 提交的结点 | 行数 | 字符数 |
|---|---|---|---|---|
| （空文件，0 字节） | 无行结束标记；EOF 时未读到过字节 → 不提交尾行 | 无 | 0 | 0 |
| A | EOF 时 buffer = "A" 且有未提交字节 → 提交尾行 | "A" | 1 | 1 |
| A\n | 'A' 入 buffer；'\n' 提交结点 "A" 并复位标记；EOF 无未提交字节 → 不再提交 | "A" | 1 | 1 |
| \n | '\n' 提交一个**空结点** | "" | 1 | 0 |
| A\n\n | 第 1 个 '\n' 提交 "A"；第 2 个 '\n' 提交 "" | "A"、"" | 2 | 1 |

**关键实现标记**：每行维护 sawByte（自上一个行结束标记以来是否读到过字节）。
- 行结束标记 → **无条件**提交结点（保证 "\n" 得到 1 行空行）；
- EOF → **仅当 sawByte 为真**才提交尾行（保证 "A\n" 不再多出一行）。
只用「buffer 是否为空」判定 EOF 尾行会把 A\n 读成 2 行，把 \n 读成 0 行。

### 6.2 CRLF / LF 读取状态机

    行缓冲 b = ""；sawByte = false
    循环取字节 ch：
        若 ch == '\n'：提交结点(b)；b 清空；sawByte = false；继续
        若 ch == '\r'：
            预读 next；若 next == '\n' 则消费之
            提交结点(b)；b 清空；sawByte = false；继续   // 单独 CR 也按行结束（见 Q4）
        否则：b += ch；sawByte = true
    EOF：若 sawByte 为真 → 提交结点(b)

不变量：**行结束标记永不进入结点内容**；一个 CRLF 只结束一行，不产生两个结点。

### 6.3 保存格式（规则 7）

- 按 next 链顺序遍历数据结点：写出 content 的全部字节，再写一个 '\n'。
- 空文档 → 写出 0 字节文件（不是写一个 '\n'）。
- 统一使用 '\n'，不要求保留原文件的 CRLF 或末尾换行形式。
- 往返不变式（T10）：保存 → 以输出文件为输入重新启动 → 行序列、每行内容、行数与字符数一致。

- 改变链接：i、d、e、q。

## 8. 性能分析（前提必须写清）

符号：n = 数据结点数；L = 当前/目标行内容长度；m = needle 长度；C = 全部行内容字符总数。

| 操作 | 前提 | 时间复杂度 | 说明 |
|---|---|---|---|
| g <行号> 定位 | 只有行号 | O(k)，k 为目标行号（双向可从近端走则 O(min(k, n-k))） | **按行号定位必须遍历**，无法 O(1) |
| n / u / f / l | 持有 current / 哨兵 | O(1) | 不涉及内容 |
| 插入（已持有 p） | 已持有目标结点 | 改链接 O(1) + 内容拷贝 O(L) | 指导书要求把这部分与「先按行号找结点」分开算 |
| 删除（已持有 p） | 已持有目标结点 | 摘链 O(1) + free O(1) 摊销 | 不需再遍历 |
| 替换整行 r | 已持有 current | O(L) 分配与拷贝 | 无匹配概念 |
| 替换子串 s | 已持有 current | O(L · m) 最坏（两遍朴素匹配） | 优化路径：KMP / std::string::find 可到 O(L + m)，非必需 |
| 查找 / | 持有 current | O(n · L · m) 最坏；从当前行起计 | 空文档 O(1) 返回未找到 |
| 显示 p | — | O(n + C) | 行号在一次遍历中累加得出 |
| 统计 c | — | O(n + C) | 字符数必须读完内容 |
| 保存 w | — | O(C) | 顺序写出 |
| 重新读入 e | — | O(文件字节数 + n) | 含释放旧树 |
| 退出 q | — | O(n) | 全量释放 |

**结论句（可直接引用）**：「已持有目标结点指针时的链接修改是 O(1)（插入另加一次 O(L) 内容拷贝）；而先按行号寻找目标结点是 O(n)。因此插入/删除的代价描述必须区分这两种前提。」

| T13 | 较长行及多次替换、删除、重新读入 | 无静默截断，重复操作后状态正确 | 5000+ 字符行长完整往返，无截断；多轮操作后 I1-I4 全部不变式成立 | R3、R5、R6 |

### 9.1 最易写错的 5 个点

1. **删除时先释放后取值**：必须先在删除前暂存 next / prev，再释放；否则用悬垂指针选择新 current（T02、T03）。
2. **EOF 尾行判定**：只用「buffer 是否为空」会把 A\n 读成 2 行、把 \n 读成 0 行；必须引入 sawByte（T09）。
3. **aaa 中 aa→b 得 bb**：命中的读指针应 += m 而不是 +1；同时禁止回头搜索（T08）。
4. **替换子串按等长假设写越界**：必须先算出 newLen 再分配，变长/变短/为空统一走新数组路径（T07、T13）。
5. **替换后误换结点或误改 current**：规则 2 明确「替换整行或子串不改变当前行所对应的结点」；同时非法输入后必须保持原状态（T04、T05）。
